# 粘液科技助手 - 工作站配置管理器

## 使用说明

### 简介
这是一个完全独立的HTML文件，包含了所有必要的CSS和JavaScript代码，可以直接通过file://协议在浏览器中打开使用，无需Web服务器。

### 使用方法
1. 直接双击 `工作站配置管理器.html` 文件
2. 或者在浏览器地址栏输入完整的文件路径，例如：
   ```
   file:///F:/Minecraft/备份/jsMacros/slimefun-helper/html/工作站配置管理器.html
   ```
3. 导入配置：点击"导入"按钮，选择本地JSON文件导入配置，导入后会在列表中显示导入的配置
4. 导出配置：点击"导出"按钮，将当前配置导出为JSON文件，文件名默认是"工作站.json"，可以在导出后手动修改文件名

### 功能特性
- **工作站配置管理**：添加、编辑、删除工作站配置
- **单方块工作站**：配置输入/输出槽位，支持按钮触发合成
- **多方块工作站**：可视化结构编辑器，支持自定义结构布局
  - 自动删除空白行列，优化结构存储
  - 特殊方块标记（输入/输出容器、交互方块）
  - 输出容器位置可选，默认使用输入容器位置
- **搜索和过滤**：按ID、名称搜索，按类型过滤
- **排序功能**：按优先级、ID、名称排序
- **槽位配置**：支持范围表达式（如"1-5,7,10-12"）
- **合成配置**：支持自动合成、按钮触发、交互触发三种方式
- **数据验证**：完整的配置验证，确保数据正确性
- **JSON预览**：导入/导出JSON配置文件
- **响应式设计**：适配不同屏幕尺寸
- **localStorage持久化**：自动保存配置到浏览器本地存储

### 数据存储
- 使用localStorage自动保存配置，刷新页面不会丢失数据
- 使用"导出"功能可以将配置保存为JSON文件备份
- 使用"导入"功能可以从JSON文件加载配置

### 浏览器兼容性
- 推荐使用现代浏览器（Chrome、Firefox、Edge、Safari）
- 不需要网络连接
- 不需要任何插件或扩展
- 支持localStorage的浏览器

### 故障排除
1. 如果页面无法正常显示，请确保使用现代浏览器
2. 如果某些功能不工作，请检查浏览器控制台是否有错误信息
3. 确保文件路径中不包含特殊字符
4. 如果数据丢失，检查浏览器是否启用了localStorage
5. 导入失败时，请检查JSON文件格式是否正确

### 技术架构

#### 代码结构
```
html/
├── 工作站配置管理器.html  # 主HTML文件
├── js/
│   ├── app.js                        # 主应用逻辑
│   ├── utils/
│   │   ├── dialog.js                 # 弹窗工具函数
│   │   └── validator.js              # 数据验证器
│   └── lib/                          # 第三方库
│       ├── zepto.min.js              # DOM操作库
│       └── tailwindcss.min.js        # CSS框架
├── css/
│   └── design-system.css             # 自定义样式
└── config/
    └── 工作站.json                   # 示例配置数据
```

#### 核心模块

**1. 应用状态管理 (app.js)**
- 工作站列表管理
- 搜索、过滤、排序
- localStorage持久化

**2. 数据验证 (validator.js)**
- 工作站配置验证
- ID格式验证（支持连字符）
- 方块ID验证
- 槽位配置验证
- 相对位置验证

**3. 弹窗系统 (dialog.js)**
- Toast提示（成功/错误/警告/信息）
- 确认对话框
- 输入对话框
- Promise-based API

**4. 编辑器功能**
- 单方块/多方块结构编辑
- 可视化网格编辑器
- 特殊方块标记管理
- 槽位范围表达式解析

#### 代码优化

项目经过两轮深度优化，主要改进包括：

**性能优化**
- 空白行列删除：从两次循环优化为一次遍历（使用Set集合）
- 事件绑定：使用事件委托减少监听器数量
- DOM查询：减少重复查询，缓存常用元素

**代码质量**
- 消除约150行重复代码
- 提取通用逻辑为辅助函数
- 使用配置对象替代硬编码
- 统一的事件处理模式

**可维护性**
- 模块化设计（dialog.js、validator.js独立封装）
- 清晰的函数命名和注释
- 配置驱动的特殊标记处理
- 统一的模态框控制
